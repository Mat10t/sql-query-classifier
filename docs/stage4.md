# Этап 4. Расширение корпуса, группы признаков и выборки

## Расширение корпуса

На этапе 3 в диапазон от 1 до 100 мс попадали 17 из 274 запросов. Чтобы этот диапазон был представлен в обучении и тесте, в корпус добавлены 96 запросов по восьми новым шаблонам. Для каждого шаблона выбраны две начальные позиции и шесть вариантов ширины диапазона ключей в фильтре. Получилось 12 запросов на шаблон. [Генератор](../src/db/build_extended_workload.py) и [SQL всех запросов](../data/queries/v2/queries.json).

| Шаблон | Что вычисляет запрос |
|---|---|
| order_status_totals | Число заказов и их общую стоимость по статусам |
| top_parts_by_quantity | 20 деталей с наибольшим суммарным количеством в позициях выбранных заказов |
| customer_urgent_orders | Число покупателей с хотя бы одним срочным заказом в каждом сегменте |
| inventory_by_brand | Стоимость запасов деталей по маркам |
| supplier_ship_modes | Число позиций и их суммарную стоимость по способам доставки для выбранных поставщиков |
| order_price_changes | Среднее абсолютное изменение стоимости между соседними заказами одного покупателя в выбранном диапазоне |
| part_stock_extremes | Минимальную и максимальную закупочные цены по деталям с суммарным запасом свыше 20 000 единиц |
| nation_balance | Средний баланс покупателей по странам и сегментам |

Расширенный корпус содержит 370 запросов из 39 шаблонов. Все запросы измерены в одной сессии PostgreSQL 16.4 по протоколу этапа 1. После прогрева каждый запрос выполнен пять раз, за время выполнения принята медиана. Из 96 добавленных запросов 77 попали в диапазон `1 <= t < 100` мс. Во всём корпусе в этот диапазон попали 93 запроса из 12 шаблонов. [Распределение по времени и шаблонам](../reports/stage5/v2/coverage.json).

| Время выполнения | Весь корпус | Обучение по шаблонам | Тест по шаблонам |
|---|---:|---:|---:|
| Меньше 1 мс | 123 | 117 | 6 |
| От 1 до 10 мс | 51 | 39 | 12 |
| От 10 до 100 мс | 42 | 31 | 11 |
| От 100 мс | 154 | 121 | 33 |
| Всего | 370 | 308 | 62 |

Верхняя граница каждого интервала исключена. Микрозапросы входят в корпус с тем же весом, что и остальные запросы.

## Разбиение на обучение и тест

В основном разбиении все варианты одного шаблона попадают в одну выборку. В сравнительном случайном разбиении единицей отбора служит отдельный запрос. Назначения исходных запросов сохранены, для добавленных шаблонов и запросов использован seed 42. При распределении известны только идентификаторы запроса и шаблона. [Фиксированные назначения](../reports/stage5/v2/splits.csv).

| Разбиение | Обучение (запросов / шаблонов) | Тест (запросов / шаблонов) | Общих шаблонов |
|---|---:|---:|---:|
| template | 308 / 29 | 62 / 10 | 0 |
| random | 277 / 39 | 93 / 34 | 34 |

## Входные признаки

Перечень в [columns.py](../src/features/columns.py) обязателен для обучения. Новый столбец CSV или отсутствие обязательного признака останавливает запуск. Служебные и целевые колонки разрешены в датасете и исключены из входа модели.

| Группа для --groups | Смысл | Число признаков |
|---|---|---|
| optimizer | Total Cost и Startup Cost корневого узла | 2 |
| cardinality | оценки числа строк и ширины строки корневого узла | 2 |
| structure | число узлов плана | 1 |
| operators | число узлов каждого из восьми типов операций | 8 |
| sql | длина, токены и конструкции SQL-текста | 9 |

Без параметра `--groups` используются все 22 признака. Для обучения только по признакам плана надо указать `--groups optimizer cardinality structure operators`. Состав выборок при смене групп сохраняется.

## Порог бинарного классификатора

Запрос получает метку тяжёлого, если его время строго превышает 75-й процентиль времени обучающих запросов. В основном разбиении порог равен 515.76775 мс, в случайном - 521.07 мс. Один порог применяется к обучению и тесту каждого разбиения. Масштабирование признаков также обучается только на обучающих запросах. [Порог для template](../reports/stage5/v2/binary/template/metrics.json) и [порог для random](../reports/stage5/v2/binary/random/metrics.json).

## Как проверить

Команды проверки выполняются из корня проекта.

```bash
python -m src.db.build_extended_workload --check
python -m src.checks.check_collection --queries data/queries/v2/queries.json --dataset data/processed/v2/query_dataset.csv --measurements data/processed/v2/measurements.csv --plans data/processed/v2/plans.jsonl
python -m src.checks.check_leakage --dataset data/processed/v2/query_dataset.csv --plans data/processed/v2/plans.jsonl
python -m unittest discover -s tests -p test_extended_corpus.py
```

Первая команда сверяет тексты SQL и назначения выборок с результатом генерации. Проверка журнала подтверждает 370 запросов и 2220 запусков с учётом прогрева. Проверка признаков пересчитывает 22 поля из SQL и планов EXPLAIN. На зафиксированных выборках проведено [сравнение базовых моделей этапа 5](stage5.md).
